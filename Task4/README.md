# Категории рисков и возможные проблемы системы «Медикаменты»

Данный документ содержит систематизированный обзор основных категорий рисков, влияющих на производительность, надёжность и безопасность системы. Для каждой категории перечислены конкретные проблемы и потенциальные последствия.

---

## 1. Инфраструктура

### 1.1. Файловый сервер и хранилища данных

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Общий файловый диск без разграничения доступа | Конкуренция за ресурсы при одновременном доступе множества сотрудников; рост нагрузки на файловый сервер |
| Отсутствие шифрования данных at rest | При внедрении шифрования — потенциальный рост нагрузки на CPU сервера без аппаратного ускорения |
| Отсутствие резервного копирования или нерегламентированные бэкапы | Риск полной потери данных; при восстановлении — простои бизнес-процессов |
| Хранение всех данных (включая архивные) на одном диске | Деградация скорости чтения/записи по мере заполнения; отсутствие tiered storage |
| Отсутствие мониторинга дискового пространства и I/O | Внезапная нехватка места приводит к остановке 1С и файловых операций |

### 1.2. Сетевая инфраструктура

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие сегментации сети (нет DMZ, нет изоляции серверов) | Широковещательный шторм; компрометация одного сегента влияет на всю сеть |
| Передача данных по незашифрованным каналам (SMB, SQL без TLS) | Риск перехвата; при внедрении TLS — дополнительный latency без оптимизации |
| Отсутствие VPN для удалённого доступа | Невозможность безопасной удалённой работы; простои при невозможности доступа из филиалов |
| Единая сеть для рабочих станций, серверов и IoT-устройств (ККМ) | Конкуренция за пропускную способность; риски от атак через периферийные устройства |

### 1.3. Аппаратные ресурсы

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие отказоустойчивости (RAID, кластеризация) | При выходе из строя диска/сервера — полный простой |
| Отсутствие горизонтального масштабирования | Пиковые нагрузки (утренний приём пациентов, конец месяца) приводят к деградации |
| Общие ресурсы для файлового сервера и 1С | Конкуренция за CPU/RAM/I/O между приложениями |

## 2. Программное обеспечение

### 2.1. 1С в файловом режиме

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Файловый режим 1С (без PostgreSQL/Oracle) | Ограничение на одновременных пользователей; блокировки при конкурентном доступе |
| Отсутствие тонкой модели доступа в 1С | Сотрудники видят избыточные данные; рост объёма передаваемых данных |
| Прямой доступ к файлам базы через сетевую шару | Риск повреждения базы при обрыве сети; блокировки транзакций |
| Ручное обновление конфигураций 1С | Длительные окна простоя при обновлениях; риск ошибок |

### 2.2. Отсутствующие или не внедрённые системы

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие CRM/портала пациента — ручная запись | Узкое место: ресепшен как единственный канал записи; простои при отсутствии сотрудника |
| Отсутствие централизованного логирования | Невозможность оперативного выявления проблем; рост времени простоя |
| Отсутствие Data Catalog — данные «размазаны» | Рост времени на поиск и анализ данных; неэффективная работа аналитиков |
| Отсутствие DLP-системы | Неконтролируемые утечки; при внедрении — необходимость оптимизации производительности сканирования |
| Отсутствие SIEM-системы | Медленное обнаружение инцидентов; рост времени реакции на сбои |

### 2.3. Excel-файлы как средство учёта

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Дублирование данных в Excel и 1С | Конфликты версий; время на ручное согласование расхождений |
| Ручное ведение журналов и реестров | Человеческий фактор; ошибки ввода; дублирование труда |
| Отсутствие версионирования Excel-файлов | Работа с устаревшими данными; повторная обработка |
| Одновременная работа нескольких пользователей с одним файлом | Блокировки файлов; потеря данных при конфликте |

## 3. Интеграция

### 3.1. Интеграция между системами

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие API между 1С, CRM, EMR и будущими системами | Ручной обмен данными; задержки в актуальности информации |
| Интеграция с лабораторией по API не описана детально | Риск потери данных анализов; повторные запросы; недовольство пациентов |
| OLE-интеграция 1С с внешними системами | Нестабильность; зависание 1С при проблемах с внешним приложением |
| Нет единого идентификатора пациента между системами | Дублирование записей; ошибки при сопоставлении данных |

### 3.2. Внешние интеграции

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Передача данных по почте без шифрования | Задержки при проверке вложений антивирусом; риски компрометации |
| Отсутствие автоматизированного биллинга | Ручной учёт платежей; расхождения; время на сверку |
| ККМ без централизованного управления | Потеря данных при сбоях кассы; ручное восстановление |

### 3.3. ETL и аналитика

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие озерка данных и ETL-процессов | Аналитик работает с «сырыми» Excel-файлами; неэффективно |
| Нет обезличивания данных для аналитики | Риск утечки PHI; необходимость ручной обработки перед выгрузкой |
| Ручная подготовка отчётов | Время аналитика тратится на сбор данных, а не на анализ |

## 4. Персонал

### 4.1. Организационные риски

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие ролевой модели доступа (RBAC) | Сотрудники имеют избыточный доступ; риск ошибок и утечек |
| Аналитик работает с необезличенными данными | Риск утечки PII/PHI; неэффективное использование ресурсов защиты |
| Нет формализованного обучения сотрудников по безопасности | Человеческий фактор: фишинг, неправильная обработка данных |
| Зависимость от отдельных сотрудников (ключевые знания не задокументированы) | Простой при уходе/отсутствии ключевого сотрудника |

### 4.2. Нагрузка и процессы

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Ручные операции (двойной учёт в Excel и 1С) | Избыточная нагрузка на персонал; ошибки; недовольство |
| Ресепшен — единственный канал записи на приём | Ограниченная пропускная способность; очереди; простои врачей |
| Отсутствие SLA и метрик производительности | Невозможность объективной оценки и планирования улучшений |

## 5. Процессы

### 5.1. Управление данными

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие политики сроков хранения ПДн и медданных | Накопление «мёртвых» данных; рост объёма хранилищ; замедление запросов |
| Нет процесса удаления/архивирования данных | Бессрочное хранение всех данных; неэффективное использование ресурсов |
| Отсутствие Data Lineage — непонятно происхождение данных | Затраты времени на верификацию данных; ошибки в отчётности |
| Избыточный сбор данных в анкетах | Увеличение объёма БД; замедление операций ввода/вывода |

### 5.2. Безопасность и инциденты

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Отсутствие формализованного процесса реагирования на инциденты | Затягивание реакции; рост времени простоя при инцидентах |
| Нет мониторинга и алертинга | Инциденты обнаруживаются постфактум; рост ущерба |
| Отсутствие регулярных аудитов безопасности | Накопление скрытых уязвимостей; внезапные сбои при проверках |
| Нет процедуры расследования инцидентов | Повторяемость инцидентов; отсутствие извлечённых уроков |

### 5.3. Регуляторное соответствие

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Высокая вероятность несоответствия 152‑ФЗ | Риск штрафов, предписаний, приостановки деятельности |
| Отсутствие прозрачности для субъектов ПДн | Невозможность обработки запросов пациентов на удаление/корректуру данных |
| Нет документации обработки ПДн | Затраты времени при регуляторных проверках; риски предписаний |

## 6. Архитектура и проектирование

### 6.1. Архитектурные практики

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Безопасность не закладывалась при проектировании (нет Privacy by Design) | Постфактумное внедрение защиты — дороже и сложнее; простои при переработке |
| Нет единого источника истины по пациентам | Дублирование записей; ошибки при назначении; повторные анализы |
| Отсутствие API-first подхода | Жёсткая耦合 систем; сложность замены/масштабирования компонентов |

### 6.2. Масштабируемость

| Проблема | Потенциальное влияние на производительность |
|----------|---------------------------------------------|
| Монолитная архитектура (1С файловый режим + Excel) | Невозможность горизонтального масштабирования отдельных компонентов |
| Отсутствие кэширования и очередей задач | Пиковые нагрузки напрямую влияют на все системы |
| Нет разделения на read/write модели | Конкуренция за ресурсы между операционными и аналитическими запросами |
